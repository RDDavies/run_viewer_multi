📊 Overview

RunViewerMulti is a GPS telemetry comparison tool for motorsport data (presently only SoloStorm data). Load two or more run CSV files recorded from SoloStorm, then play them back simultaneously on an interactive map while comparing speed, gear, throttle, brake, RPM, sector times, and G-forces side by side.

All processing happens locally in your browser — no data is uploaded anywhere.

ℹ️
The viewer works best with at least two runs loaded so you can compare deltas. A single run still shows all live metrics and the GPS trace.

Key capabilities

Multi-run overlayUp to as many runs as you want, each assigned a distinct color, all rendered simultaneously on the map.
Synchronized playbackA shared timeline drives all runs in lockstep. Adjustable speed: ½×, 1×, 2×, 5×, 10×.

📄 CSV Format

The viewer expects CSV files with a specific set of columns. Column names are case-insensitive and matched by header name.

ColumnRequiredDescription
Time (ms) or tRequiredTimestamp in milliseconds from the start of the session.
Latitude or latRequiredGPS latitude in decimal degrees.
Longitude or lonRequiredGPS longitude in decimal degrees.
Speed (mph) or speedOptionalVehicle speed in miles per hour.
RPM or rpmOptionalEngine revs per minute.
Gear or gearOptionalCurrent gear (numeric). Shows "N" for neutral/0.
Throttle (%) or throttleOptionalThrottle position 0–100.
Brake (%) or brakeOptionalBrake pressure 0–100.
Lat G or latgOptionalLateral G-force in g.
Lon G or longOptionalLongitudinal G-force in g.
Lap or lapOptionalLap number. When present, the viewer groups data into individual laps for selection.
✅
Lap detection: If a Lap column is present, the viewer automatically splits the session into individual laps. You can then select which lap to display per run using the lap selector in the run pill. If no lap column is present, the entire session is treated as a single run.

📂 Loading Runs

There are three ways to load CSV files into the viewer:

  1. Initial drop zone — When the viewer first opens, a full-screen drop zone appears. Drag one or more CSV files onto it, or click to open a file browser. Multiple files can be loaded at once.

  2. Header drop zone — After runs are loaded, a dashed drop area is visible in the header bar (between the title row and the run pills). Drag additional CSV files here at any time to add more runs to the session.

  3. + Add Run button — Click the + Add Run button in the top-right of the header to open a file picker and select additional CSVs.

ℹ️
Runs are assigned colors automatically from a fixed palette. Each new run gets the next available color. Removing a run frees its color slot for future runs.

Removing runs

Each loaded run appears as a pill in the header. Click the ✕ on any pill to remove that run and its map trace. To remove all runs at once, click ✕ Clear All.

Selecting a lap

If your CSV contains a Lap column, a lap selector dropdown appears inside each run pill. Use it to switch which lap is shown for that individual run — each run can display a different lap independently.

🗺️ Map View

The map occupies the left two-thirds of the screen and shows all run GPS traces as colored polylines. A moving marker on each trace represents the current playback position.

Map layers

A Map / Satellite toggle in the top-right corner of the map switches between:

  • Dark street map (CartoDB Dark Matter) — good for seeing the track layout clearly against a minimal background.
  • Satellite imagery (Esri World Imagery) — good for correlating track features with real terrain.

Sector markers

When sector times are detected, yellow numbered circles appear on the map at each sector boundary. These are positioned on the baseline run's GPS trace.

Map click seek

Click anywhere on or near the GPS trace to jump all runs to that physical location. See Map Click Seek for full details.

Map navigation

  • Scroll / pinch — zoom in and out
  • Click + drag — pan the map
  • Double-click — zoom in one level
✅
The map auto-fits to show all loaded run traces when a new run is added. Zoom and pan freely after that — the view won't snap back unless you add another run.

⏱️ Sector Times

The sector times table appears in the lower section of the right panel. Sectors are automatically detected from peaks in the speed data — a new sector begins each time the vehicle slows significantly through a defined threshold.

Table columns

ColumnDescription
#Sector number.
Per run (one col each)Sector time in seconds. The fastest time in each sector is shown in bold. A delta vs. the baseline run is shown below the time in small text (−0.2s or +0.4s). Distance driven in that sector is shown below the delta.
Total rowTotal lap time and total distance per run.

Active sector highlight

The sector row corresponding to the current playback position is highlighted so you always know which segment you're watching.

Distance per sector

Each sector cell shows the distance driven in that segment:

  • Shortest distance — shown in green with the actual value in parentheses, e.g. (843ft).
  • Longer distance — shown in red with only the difference from the shortest, e.g. (+37ft). This highlights where a run took a wider or longer line.
✅
Distance is calculated from GPS coordinates using an equirectangular approximation. It reflects actual path length driven, not straight-line distance between sector boundaries. A longer distance in a sector usually means a wider line.

🎯 Baseline & Deltas

All delta times in the sector table and the per-run live metric rows are calculated relative to a baseline run.

Selecting a baseline

The Baseline dropdown is located below the sector table header. Options:

  • Auto (fastest) — The run with the shortest total lap time is automatically used as the baseline. This updates dynamically as runs are added or removed.
  • Any loaded run — Select a specific run by filename to lock it as the baseline regardless of lap times.

Reading deltas

Deltas are shown in the sector table below each sector time, and in the live metrics panel next to each run's speed readout:

  • −0.3s — This run is ahead (faster) of the baseline by 0.3 seconds at this point.
  • +0.5s — This run is behind (slower) than the baseline by 0.5 seconds at this point.
  • The baseline run itself shows no delta (or 0.0s).
ℹ️
After a map-click GPS seek, the live delta display may not be meaningful for the run that was seeked, since the time offsets between runs are intentionally different. Deltas in the sector table are always based on full sector timing and remain accurate.

✂️ Trim Controls

The trim bar sits between the map and the playback controls. It lets you define custom start and finish GPS waypoints so that out-laps, in-laps, or paddock sections are excluded from analysis.

[ Set Start ] 0:12.4 ───── [ Set Finish ] 1:05.2 ───── [ Reset Trim ]

Setting the start point

  1. Scrub the timeline (or play) to the moment where you want the lap to start — e.g., the moment the baseline run crosses the start/finish line.

  2. Click Set Start. The GPS location of the baseline run at the current timeline position is recorded as the start waypoint.

  3. The trim is immediately applied to all runs — each run independently finds the closest GPS point to that waypoint and trims its data from that point forward.

Setting the finish point

Same process: scrub to the desired finish moment, then click Set Finish.

Reset

Click Reset Trim to remove both waypoints and restore all data for all runs.

⚠️
Location-based, not time-based: The trim uses GPS coordinates, not timestamps. Each run finds its own closest point to the waypoint independently. This means runs with slightly different lines will trim at slightly different timestamps — which is intentional and gives the most accurate comparison.
✅
After trimming, all sector times are fully recalculated on the trimmed data. The timeline resets to 0:00 at the new start position.

🔵 G-Force Display

The G-force circle in the lower right of the panel plots lateral (left/right) vs. longitudinal (forward/backward) G-forces in real time.

  • X axis (left/right) — lateral G. Right = right-hand cornering load.
  • Y axis (up/down) — longitudinal G. Up = braking, down = acceleration.
  • The dot is the current G reading. A fading trail shows the recent history per run (each run's dot is in its run color).
  • Reference circles are drawn at 0.5g and 1.0g.
ℹ️
G-force data requires the Lat G and Lon G columns in the CSV. If those columns are absent, the G-force display will show a stationary dot at the center.

📍 Map Click Seek

Clicking anywhere on the map aligns all runs to the same physical GPS location, rather than the same timestamp. This is the key tool for understanding what different drivers do at a specific part of the track.

How it works

  1. Click a point on or near the GPS trace on the map. Playback pauses automatically.

  2. The viewer finds the closest GPS point on the baseline run to the clicked location, and sets the shared timeline to that run's lap time at that point.

  3. For every other run, the viewer independently finds that run's own closest GPS point to the same clicked location. A per-run time offset is stored so the other run's marker sits at that location — even though the underlying timestamp may differ from the baseline.

  4. All run markers now appear at the same geographic point on the map. Live metrics reflect what each driver was doing at that exact location.

Returning to time sync

Map-click GPS offsets are cleared (all runs re-sync to the same timestamp) when you:

  • Click ■ Stop
  • Drag the timeline slider
✅
After a map-click seek you can still press ▶ Play to resume playback. Each run will advance from its GPS-aligned position, so the physical positions on the map will drift apart as each run follows its own time from that GPS point onward. This is useful for seeing who gets on throttle earlier coming out of a corner.

💡 Tips & Workflows

Comparing two drivers on the same track

  1. Load both drivers' CSV files. Select the fastest lap per driver using the lap selectors in their pills.

  2. Use Set Start and Set Finish at the start/finish line to trim to exactly one clean lap.

  3. Set the faster driver as the Baseline in the dropdown.

  4. Play at 2× speed to get a quick overview, then scrub manually to corners of interest.

  5. Click on a late-apex point in a corner to GPS-seek both runs to that location and compare brake points, throttle, and speed.

Identifying where time is lost

The sector table highlights which segments are slowest. A red delta in a sector means time is being lost there. Look at the distance column — a larger distance (red +Xft) in the same sector may indicate a wider, slower line.

Using map click for corner analysis

Click at the apex of a corner to align runs, then note:

  • Speed readout — who is carrying more speed through the apex?
  • Throttle bar — who is on throttle earlier?
  • Gear — are both in the same gear?

Then press Play and watch how the markers diverge on exit to see who accelerates harder or earlier.

Keyboard-friendly scrubbing

Click the timeline slider to give it focus, then use ← and → arrow keys for fine scrubbing frame by frame.

Satellite view for context

Toggle to Satellite when analyzing specific corners — you can see the track surface, kerbs, and runoff areas to understand the physical context of what the data is showing.
